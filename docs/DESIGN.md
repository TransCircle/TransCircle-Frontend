# TransCircle-Frontend — 设计落地说明

> **本文件不是设计规范源。**
>
> 唯一视觉规范源是仓库外的全局文档
> **`TransCircle/docs/DESIGN.md` —— 「TransCircle 设计系统 v3.0 / Spectrum·光谱」**。
>
> 一切色值、圆角、字阶、间距、阴影、动效时长、层级都以该文档 §2 为准；
> 要改值，先改那份文档，再同步三仓的 token 文件。本文件只记录**本仓特有的落地方式**。

外壳、导航、认证舞台与管理控制台的结构与 Pass 门户（TransCircle 仓库）保持一致；
两站共用同一套交互（同一种顶栏、抽屉、页脚、状态页、控制台），差异只在内容。

  `--disabled-opacity`、`--ui-fs`、`--admin-rail-w` / `--admin-rail-mini-w` / `--admin-topbar-h`。

Nunito Brand 仅用于品牌词（`<BrandText>` 渲染时把文案里的「TransCircle」包进品牌字体，
i18n 文案保持纯文本），Space Grotesk 用于数字、时间与 eyebrow 标签。

## 2. 三套词表分治（本仓最重要的结构决定）

|          | 公共侧 `Story.module.css`      | 账户侧 `Account.module.css`          | 后台侧 `Page.module.css`                           |
| -------- | ------------------------------ | ------------------------------------ | -------------------------------------------------- |
| 页面     | 首页、阅读页                   | 投稿、我的投稿、详情、修改申请、设置 | 后台概览、各列表与详情                             |
| 正文基准 | 16px，**不得下调**             | 16px（`--ui-fs: --fs-body`）         | 允许 14px（`--ui-fs` 默认 `--fs-sm`，§5.8）        |
| 标题     | 首页 `--fs-h2`、文章 `--fs-h1` | 页标题 `--fs-h1`、详情 `--fs-h2`     | 详情封顶 `--fs-h3`                                 |
| 列表     | 卡片网格，hover 浮起 3px       | 独立行卡片（`--r-md`）               | 一张描边容器 + 发丝线分隔的行，hover `--surface-2` |
| 粉色含义 | 强调与身份                     | 强调与当前项                         | **仅表示「选中/激活」**；只读面一律 `--surface-2`  |

表单原语（TextField / Select / TagInput / Checkbox / DescriptionList / Markdown 编辑区）的字号读 `--ui-fs`：
由所在容器决定密度（公共侧与账户侧容器设为 `--fs-body`），不要在页面里逐个覆盖。改动任一侧时不要顺手把类抽到另一侧复用——分歧是设计意图。

## 3. 外壳（`RootLayout` + `App.module.css`）

- `.app`（flex column、`min-height: 100dvh`）→ 跳转链接 → `Navbar` → `main` → `.pageWrap` → `LicenseFooter`。
- `.pageWrap` 按**顶级路由段**作 key 重挂载并播放 `pageIn`；填充模式必须是 `backwards`——
  保留 transform 终态会让包装层成为 `position: fixed` 后代的包含块，阅读进度条就不再贴视口。
- **宽屏锁一屏**：根节点自报 `data-viewport-fit` 的页面（`AuthStage`、`CenteredCard`）在
  `min-width: 901px and min-height: 600px` 下把外壳钉成 `100dvh`、由 `main` 内部滚动，页脚常驻屏底；
  只认 `.pageWrap` 的直接子元素。窄屏不锁。换页时 `useLayoutEffect` 归零 `main` 的滚动，前进导航同时归零文档滚动
  （后退 / 前进交给浏览器恢复；带 hash 时让位给页面自己的定位）。滚动锁跨页解锁时不恢复离开页的位置。
- 后台路由由 `AdminShell` 持有唯一的 `<main id="admin-main">`；是否为后台路由按路由 `handle.shell`
  判定（`router/handles.ts`），`/admin/不存在` 落到 404 时 RootLayout 自己给出 `main`，标题按通配路由的 `handle.notFound` 取 404。
  换页焦点：公共页由 RootLayout 移入 `main`，后台由 AdminShell 移入 `#admin-main`（子页面已把焦点放进 main 时不抢）。
- `html { scrollbar-gutter: stable }` + 共享滚动锁（`components/admin/scrollLock.ts`，引用计数、
  gutter 感知、接管 main 滚动、弹窗档冻结 body 防 iOS 回弹）。抽屉、Modal、StepUpDialog 都走它。
- 懒加载占位与目标页同一外壳（`router/RouteFallback.tsx` 的 stage / card / page / inline），避免 chunk 落地前后换外壳。

## 4. 导航（`Navbar`）

与 Pass AppNav 同一结构：玻璃画在 `::before`（不让顶栏成为下拉的背景根）、左右两组 `flex:1` 使链接居中（≤1024 链接收起后右组改为自身宽度，品牌组拿到其余空间）。

- **站名**：横版 logo 右侧 1px 分隔线 +「故事分享」（全局 §5.3 子站规则）。站点身份放在顶栏而不是首页 hero——
  大部分读者从分享链接直接落到故事页，看不到首页；顶栏每一页都在，也把本站与外观相同的主站区分开。
  ≤480px 改为正式圆环图标（`public/brand/transcircle-icon.svg`，32px）+ 分隔线（左右各 `--s-2`）+ 站名，320px 宽、未登录（主题切换 + 登录按钮）也放得下。
  链接可访问名「TransCircle 故事分享」，包含可见站名。

- 一级：首页 · 搜索 · 投稿 │ 更多▾（同博客顶栏，本站功能与外站之间一条 1px `--line` 竖线）。
  「更多」是项目组其他站点：跨环主站、社区论坛、博客、内容搜索（成员个人外部站，带「外部」标签与 `nofollow`）、
  人物归档（开发中，`aria-disabled` 不可点）。「关于」页留到做 SEO 时再加（届时排在「投稿」之后）。
- 当前项：单条 24×3px 迷你旗帜条纹在各项间滑动（`--stripe-x` + ResizeObserver，首次不动画）。
- 账户菜单：鼠标悬停打开 / 140ms 延时关闭，触屏与键盘点击切换；头部显示显示名与管理角色，
  角色同时进入头像按钮的可访问名。菜单项激活后关闭菜单并先把焦点还给触发器（真正换页时再由 main 接管）。
- ≤1024px 收进汉堡，**抽屉自左侧滑入**，条目 40ms 交错入场；`main` 置 inert、Tab 循环、Esc 关闭。

## 5. 故事流与阅读页（公共侧）

- 首页是内容站而不是门户：**首屏留给故事，身份靠文案与顶栏站名，不靠音量**。
  页头 = 灰色定位小字「社群故事档案」（`--font-tech --fs-xs`）+ `h1`「让故事被听见」（`--fs-h2` 墨色）+ 导语（`--fs-body`），
  左对齐、右侧留白（同博客首页）；其下 `--s-6` 留白后是「最新故事」小标签与卡片网格。首页不放搜索框。
  刻意不用：粉色 eyebrow、32px 粗体标语、粉色按钮、分隔线——这四样叠在一起就是「抢眼」的来源；
  投稿入口在顶栏、「我的投稿」在头像菜单，页面里不重复。
- 搜索页 `/search?q=`：同一套页头但**居中**（`h1`「搜索故事」→ 阅读轨宽、52px 高的搜索框 → 一行说明 / 结果数，`role=status`）
  →「搜索结果」小标签 → 同一张故事卡（`pages/StoryCard.tsx`）的网格 + 分页。左对齐时阅读轨宽的输入框停在三列网格
  半中间、像被截断；居中后空状态是完整的搜索入口，出结果时也对称，且输入框位置在两种状态间不变。从顶栏进入即聚焦输入框
  （下一帧聚焦，晚于 RootLayout 的换页焦点）；关键词变了而请求尚未发出的那一帧按加载中处理，不闪「0 条」；输入停顿 300ms 即时搜索，关键词以 replace 写进 URL，
  前进 / 后退回填。旧版首页搜索链接 `/?search=` 自动改道到 `/search?q=`。
- 置顶稿**不另开分区**：置顶不一定是公告，也可能是想让更多人读到的故事。它就是同一张故事卡，
  在首页第一页排在最前，标签行最前一枚「📌 置顶」chip（`--pink-600` 底，不截断）；翻页与搜索结果里不出现。
  第一页等置顶请求结束再出卡片（置顶卡后到会把整排往后挤），等待上限 4s，超时或失败按「没有置顶」处理。
  不做特色卡、不做公告条——任何额外的置顶区都会和故事流抢首屏。
- 卡片网格列数由 `.page` 上的 `--feed-cols` 决定（>1200：3 / 769–1200：2 / ≤768：1，保证每列不窄于 §4 的 320px），骨架屏读同一个变量，
  多列时卡片与骨架共用最小高度 `--feed-card-min-h`（同一排等高），内容超出最小高度的卡片落地仍会长高；
  单列（≤768）不设最小高度，骨架按常见形态（标题 + 摘要 + 标签行 + 署名）校准。骨架只能贴近常见形态，
  摘要、标签可选、标题与摘要行数可变，落地高度随内容浮动。卡片**标题优先**：标题 → 摘要 → 贴底元信息（标签在上、署名在最下，同行对齐）。
- 阅读页：阅读轨 `--w-reading`；进度条用回调 ref 挂监听（数据到达后才挂载）；返回按钮在加载 / 出错时同样可用。

### 旗帜条纹的配额

全局 §1.5：整条条纹每屏至多一处。本仓分配：

1. 顶栏当前项 24×3px 迷你指示条（另计，§3.1 单列场景）；
2. 页脚顶部 3px 通栏（同 Pass）；
3. 认证舞台顶部整条（`scope="page"`，此时页脚条纹自动让位）。

首页不再有特色卡条纹：置顶稿与普通故事同卡后，整条条纹全站只剩页脚与舞台两处，任何页面都不会同屏。

新增任何条纹前先数一遍这张表。

## 6. 认证中转与状态页

- 登录中转、OAuth 回调、二次验证完成（四态）、认证报错：`StatusScreen variant="stage"` →
  `AuthStage`（与 Pass 登录页同一舞台：整页底 + 顶部条纹 + 卡顶 compact lockup）。
  用户在故事站与 Pass 之间跳转时前后两页视觉连贯。
- 404、错误边界：`CenteredCard` 玻璃卡（≤640 平铺）。懒加载的加载 / 失败态沿用目标路由自己的外壳
  （`router/RouteFallback.tsx`：stage / card / page / inline），失败的「重试」整页重新加载。
- 路由组件渲染 `<div>`（或上述外壳），**绝不自己渲染 `<main>`**；`ErrorBoundaryPage` 在 RootLayout 之外，用 `as="main"`。

## 7. 管理控制台（`AdminShell`）

与 Pass 控制台同一结构：保留站点顶栏；左栏 232px，视口 <1280 自动收成 60px 图标条，≤768 变成顶部横向滚动条
（换页时只动 `scrollLeft` 把当前项滚进视野）；左栏不再画 logo / 头像 / 角色（顶栏已有）。
工作区 `container-type: inline-size`（`container-name: work`），粘性玻璃标题栏高 `--admin-topbar-h`，
页内粘性工具栏偏移 = `--nav-h + --admin-topbar-h`；超宽屏内容封顶 1440px 居中，标题跟着内容左缘。

**信息架构**（路由化，每个列表、每条详情都有自己的地址）：

| 分组       | 分区     | 路由                                            | 说明                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---------- | -------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| —          | 概览     | `/admin/overview`                               | 任一后台权限可进。统计（待处理 / 新增 / 平均审核耗时 + 状态分布 + 处理流程）仅 `contribution:read`；待投票修改申请仅投票权限；「我的角色」「我的权限」（权限表：权限 / 可以做什么 / 标识，含二次验证与缺依赖提示）所有人可见，数据来自 `/me`。不画图表，导航不带角标                                                                                                                                                   |
| 内容       | 审核队列 | `/admin/review?sort=`                           | 只有待审核（后端没有流程会产生「审核中」），默认按提交时间先进先出（`submittedAt_asc`，被拒后重新提交的按重新提交时间排队），行上显示提交时间与「等待 N 天」                                                                                                                                                                                                                                                           |
| 内容       | 投稿管理 | `/admin/contributions?status=&q=&sort=&author=` | 全部状态 + 关键词（防抖写 URL）+ 作者筛选 chip + 排序                                                                                                                                                                                                                                                                                                                                                                  |
| 内容       | 修改申请 | `/admin/edit-requests?status=`                  | 选项卡只放后端真会产生的状态：进行中 / 已通过 / 已拒绝 / 已撤回 / 已失效（原投稿删除时自动置为 superseded）；守卫用 `contribution:edit-request:vote`                                                                                                                                                                                                                                                                   |
| 内容       | 评论管理 | `/admin/comments?status=&sort=` + `/:id` 详情   | 列表每行是评论入口：两行摘要 + 作者 / 所属投稿 / 发表时间（带标签字段），右侧举报数（有举报才标）与状态；状态筛选 + 排序（最新发表 / 举报最多，同数按发表时间倒序）。隐藏 / 恢复只在详情做：主栏全文、回复的评论或其下的回复、每条举报的理由与举报人；侧栏信息卡、处理卡（隐藏人与原因、连带隐藏说明、按状态写清会连带几条回复的规则）、处理记录（取自审计日志）。从列表进来的处理完退回列表并提示，别处进来的原地刷新 |
| 用户与审计 | 用户管理 | `/admin/users?q=`                               |                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 用户与审计 | 审计日志 | `/admin/audit-logs?action=&resource=`           | 每行：动作名 + 「操作者 / 对象」两个带标签字段（不用圆点串）；名称由后端解析并按读者权限下发（投稿标题需投稿读取、评论摘要需评论管理），没有名称时只给类型标记 + 短 ID；有权限时链到详情（评论链到评论详情，已删除的评论也能打开）；对象类型用下拉筛选                                                                                                                                                                 |

- `/admin` 本身不是页面，落到概览（持有任一后台权限即可进入，口径见 `api/permissions.ts` 的 `ADMIN_PERMISSION_CATALOG`）。左栏分组标签在 60px 图标条里换成发丝线。
- **按权限显示**：每个分区、卡片、按钮、链接、请求都按它背后接口的权限（与后端 `requirePermission` 一一对应）和状态 / 业务前置条件（状态机、不能封禁自己、不能给自己的申请投票等）决定显示与否；没有权限的不渲染、不请求，不出现「看得到按钮却操作不了」。权限目录改了要同步概览的权限表。
- 筛选、排序、页码全部在 URL 里，一律 `replace` 写入（`pages/admin/listParams.ts`）；`usePagedList` 的 `page` 选项接受受控页码。
- 列表行是真正的 `<Link>`（可新标签打开），带 `state.from / index`；详情 `/admin/contributions/:id`、
  `/admin/edit-requests/:id`、`/admin/users/:id` 按 `:id` 整页重挂（`router/KeyedById`），组件实例即一次详情会话。
- 标题栏由页面经 `useAdminPageHeader`（`pages/admin/header.ts`）交给外壳：标题、副标题（窄工作区隐藏）、
  返回入口（以目的地命名，窄时只留箭头）、状态徽标、所属分区（投稿详情按来源或状态归审核队列 / 投稿管理）。
- 详情布局：工作区 ≥880px 时主栏（正文 / 提议内容）+ 右侧栏（信息卡、操作卡、历史）；窄时按「信息 → 正文 → 操作 → 历史」堆叠。
- **窄屏（手机）**：工具栏里搜索框与它的「搜索」按钮始终同排，排序 / 类型下拉放不下时换到第二行；两列信息卡（`DescriptionList columns={2}`）
  按卡片自身宽度判断（半行 ≥7rem 就保持两列），不按视口退成单列；历史记录的操作者单独一行，不用圆点和状态变化串在一起；
  Markdown 编辑区工具栏 ≤640 换行，不裁掉；概览统计卡工作区 ≤480 两列。
- 写操作成功后：默认退回来源列表（从列表点进来的用 `history.back()`，焦点回到原行，见 `returnIntent.ts`）；
  勾选「连续审稿」（sessionStorage，默认关；只对未公开的稿件——待审核、已通过——出现）时按来源列表同一套查询打开下一条，
  没有下一条就回列表并提示。置顶 / 投票 / 封禁原地刷新。写成功经 `pages/admin/changes.ts` 广播，挂着的列表、概览、同一条详情各自重读。
- **审核与发布**：审核（`contribution:review`）与发布（`contribution:publish`）是两个权限（reviewer 只有前者，editor / admin 两者都有）。
  两者都有的人在待审核稿件上看到「通过并发布 / 仅通过 / 拒绝」：「通过并发布」调原子接口 `POST /admin/contributions/:id/approve-and-publish`
  （一个事务里写完通过与发布，要么都成要么都不成；需要二次验证时在任何写入之前返回，交给 step-up 重放整步）。
- **重新打开审核**：已拒绝 / 已通过（未发布）的稿件，有审核权限的人可以填原因（1–200 字，作者可见）撤回到待审核
  （`POST …/reopen`，`submittedAt` 不变，回到原来的排队位置）。作者侧显示「审核已重新打开」与原因。
- **来源说明**：后台详情的 `review` 是最近一条审核结论、`latestEvent` 是最近一条事件。待审核稿件据此区分两种来历，在正文上方说明：
  作者被拒后修改并重新提交（上一轮结论、审核人、理由，及「与被拒时的版本对照」——没改就重提时直接说明）；审核员重新打开（谁、何时、原因）。
- **审核历史与版本历史**：审核历史按事件类型显示（作者提交 / 作者撤回 / 审核 / 发布 / 隐藏 / 恢复 / 删除 / 重新打开 / 修改申请应用），
  作者动作标「作者：」而不是「审核员：」。侧栏「版本历史」列出内容快照（创建、作者修改、修改申请应用），选一个版本在主栏与当前内容逐项对照（`DiffView`）。
- **修改申请对照基准**：进行中的申请对照原投稿**当前**内容（通过时覆盖的就是它），并逐字段说明「申请后原投稿又改了哪些字段、这份申请会不会覆盖它们」；
  已结束的申请改用申请时的内容（接口 `baseSnapshot`）对照，否则已通过的申请只会显示「没有改动」。原投稿已删除时隐藏投票、去掉投稿链接。
  投票带上对照的原投稿版本（`expectedContributionVersion`）：打开之后原投稿又被改过，后端拒绝这一票（`CONTRIBUTION_CHANGED`），
  页面刷新对照并提示，确认后再投——决定性的一票不会覆盖没看过的改动。存量的 `in_review` 申请与 `pending` 同属「待处理」。
  读者侧申请表单：摘要框留空 = 不改；要删掉摘要须勾选「申请删除现有摘要」（发送空串）。
- **没改就重提**按内容判断（接口 `contentVersions.sameAsLastDecision`），不按快照号：作者原样保存、改了又改回也算没改。
  审核历史逐条显示内部备注（按内部备注权限），隐藏 / 删除等处置的说明在这里看。
- **机制透明**：操作卡底部的「规则说明」逐条写清当前状态下各操作的真实后果，文案（i18n `adminRules.*`）必须能在
  `TransCircle-Backend/src/routes/` 找到对应实现（单人审核即生效、通过后仍需发布、隐藏/删除/封禁需二次验证、
  已发布须先隐藏才能删、修改申请票数门槛取接口 `votes.required`、自己的申请不能投票、每人一票等）。后端规则变了，这里要同步改。

## 8. 原生控件政策（本仓保留的硬约束）

文本输入**必须**保持原生 `<input>` / `<textarea>`（中文输入法组字需要原生元素），只关掉原生**外观**（见 `Field.module.css`）。
粗指针下输入字号抬到 16px（iOS 聚焦缩放）。Select / Checkbox / TagInput 在 `src/components/ui/` 自绘；
不要再造第二套，也不要退回原生 `<select>` 或 `window.confirm()`。

可访问性优先于规范字面值的取舍：Checkbox 对勾用墨色 `--on-pink`（白色对勾在 `--pink-600` 上仅约 1.9:1，
达不到非文本 3:1）。

## 9. 动效与降级

- 全局降级在 `index.css` 末尾，用 `!important` 压过一切组件声明；组件内一般无需再写 reduced-motion 块
  （例外：动画停住后会停在不可见状态的元素，如 StepUp 成功对勾的描边，需要就近补终态）。
- `.reveal` 默认 `opacity: 0`，每条降级路径都必须把它恢复可见；`will-change` 只在入场前挂。
- 主题切换用 View Transition + `clip-path` 圆形扩散，时长与缓动读 `--dur-3` / `--ease-out`。
